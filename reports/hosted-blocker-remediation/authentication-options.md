# Authentication CPU decision record — October 20, 2026

## Current decision

**Unresolved release blocker.** Keep the existing credentials and Argon2id implementation unchanged. No third-party service, identity tenant, email channel or passwordless flow was activated. No user export/import or credential migration ran. This investigation found documented Free candidates, not an already qualified replacement. It would be inaccurate to claim that secure no-billing authentication is impossible; it would also be inaccurate to mark any candidate PASS without account-specific and end-to-end verification.

Actual hosted trace evidence from the baseline measures 52–200 ms in the password Worker. Workers Free allows 10 ms per HTTP invocation; occasional execution flexibility is not a capacity guarantee. Parameters remain Argon2id v19, memory 19,456 KiB, two iterations, parallelism one, 32-byte output. A Worker service binding does not remove the called Worker's CPU limit. Raising limits, weakening parameters, relying on rollover, or splitting secret-dependent computation into an unverified multi-request protocol is not the remediation. [Cloudflare limits](https://developers.cloudflare.com/workers/platform/limits/#cpu-time).

## Existing-user compatibility gate — mandatory before selection

1. Keep D1 `app_users.id`, social identities, credentials, sessions, saved references, franchise progress and independent erasure ledger authoritative and unchanged during investigation. Do not export real hashes or reuse production secrets as a test.
2. Start with isolated synthetic PHCs generated by the existing native implementation at the exact parameters, including long/Unicode passwords and imported historic hashes. Document each unsupported PHC explicitly; no forced reset or silent algorithm downgrade.
3. For a managed provider, bind `(issuer, subject)` to the immutable existing D1 user ID through a verified mapping. Prove verified ownership/linking rather than email-only account merging. Validate signature algorithm, issuer, audience, nonce/state/PKCE as applicable, expiry and revocation before issuing the existing D1 session. Do not accept a browser-supplied user ID.
4. For an external native executor, preserve the entire existing PHC string and repository/session format. Prove only the approved internal caller can submit bounded requests, responses fail closed, requests cannot replay, credentials are neither logged nor cached, and executor outage never falls back to insecure verification. Measure every remaining Cloudflare hop's CPU and actual service limits.
5. Test registration, valid/invalid verification, concurrent sessions, reset delivery/redemption/replay/expiry, password change, lockout, disabled/deleted users, account erasure, web/native flows, missing credentials, provider outage, rate limiting, secrets and rollback. Password reset must not leave two authoritative credentials accepting different passwords. Preserve existing sessions unless a separately reviewed security event requires revocation.
6. Stage a reversible, per-user/provider cutover only after synthetic proof. Retaining old hashes is not sufficient rollback after a password changes at a different authority: fence old credentials for migrated users, record authority/version, synchronize verified changes or keep those users on the new authority. Do not restore stale passwords on rollback. No migration is approved by this document.

## Recommendation for owner review

First approve a synthetic compatibility proof for a stateless native Argon2 executor if retaining the exact password algorithm is mandatory. This has the smallest credential-data change, but Free-host cold starts and an authenticated external endpoint must meet the availability/security bar. If a managed identity provider is preferred, approve a synthetic Firebase/Auth0 evaluation with explicit hashing-policy, recovery-delivery and identity-mapping review. Keep ten-D1 product storage unchanged in either case.

The precise present blocker is that the only configured password execution path exceeds its Free CPU budget, while no alternative has a verified no-payment account, approved trust boundary, existing-user compatibility proof, complete recovery and measured Worker CPU. Public pricing eligibility alone does not close that blocker. SSR/feed corrections can be reviewed independently; no beta/production GO is recommended.
