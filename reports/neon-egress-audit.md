# Neon egress audit — September 27, 2026

> Follow-up live environment audit: [Environment and scheduler findings](neon-environment-scheduler-audit.md). The scheduled GitHub search indexer had 23 failed runs and no successful runs in the inspected window; its latest eight failures explicitly lack `DATABASE_URL`. Its high code-based potential below is not evidence of actual nightly production reads. Historical ingestion schedules were also substantially more frequent than today's eight daily Cloudflare triggers. See the follow-up for deployment bindings, historical overlap, and unresolved destination comparisons.

## Evidence and limits

Reported usage: **6.46 GB / ~23 days**, approximately **281 MB/day** (decimal units). This is database-to-client transfer, not browser page weight. App-server reads, scripts and scheduled workers count even with no human visitors. Larger HTTP responses do not necessarily imply larger Neon reads, and HTTP compression does not reduce database transfer.

Production's configured database most recently returned PostgreSQL `53000` (quota exceeded); the live auth endpoint returned 500. No production content was downloaded or changed in this audit. A local aggregate-only check found empty `content_candidates`, `canonical_stories`, `story_evidence` and `three_and_out_snapshots` tables; `search_documents` was absent. Local data cannot support representative byte estimates. Rankings below are **code-based likelihood, not measured attribution**. Current checked-in schedules may differ from deployed schedules and from the preceding 23 days.

## Behavior and freshness

- No production data deletion, production configuration changes, deployments, migrations or billing changes.
- No new authentication/session cache; revoked sessions remain checked against the database.
- No arbitrary top-N cap on player histories, clustering candidates, evidence, video catalogs or search corpus.
- Public historical data may lag an import by up to 60 seconds in a warm process. Film Room uses 60-second Next revalidation (stale-while-revalidate may extend this until a successful refresh). This is the intended caching freshness tradeoff.
- Historical cache bounds each query function to 32 entries, shares pending requests, never retains rejected promises, and clones results before handing them to callers.

## Production confirmation after quota recovery

1. Check Neon transfer **per project/branch and client region**. Verify Vercel, Cloudflare and Actions point to the intended database, and identify developer scripts using production URLs. Do not log connection strings.
2. Inspect Cloudflare invocation counts, Actions run histories (including retries/manual runs), and Vercel route request counts over the same 23-day window. Confirm no old deployment or duplicate scheduler remains active.
3. If `pg_stat_statements` is enabled, record its reset timestamp and top queries by **calls and rows**, not just execution time. Use normalized query text; do not export data values. A query returning many bytes can be fast. Rows are not bytes.
4. For each top query, sample the exact **old and new projection** using SQL-side `avg(pg_column_size(...))` over a bounded sample; return only aggregate counts/sizes. Storage/TOAST size and PostgreSQL wire encoding differ, so call this an estimate. Avoid `SELECT *` table dumps to measure egress.
5. Estimate `calls/day × rows/call × projected bytes/row`, then compare against ~281 MB/day. Record both cache hit/miss and cold-start rates. PostgreSQL statistics alone do not measure transferred bytes.
6. After deployment compare 24–48 hours of Neon network transfer with similar ingestion volume and traffic. No guaranteed savings percentage is claimed without this baseline.

Largest follow-up if indexing dominates: a durable source fingerprint/checkpoint manifest, pagination by stable IDs, and complete-per-document chunk commits. It must detect source metadata/evidence association changes and resume partial failures before skipping content reads. This audit does not claim to have implemented that larger indexer redesign.
