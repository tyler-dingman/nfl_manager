Current architecture and audit findings
SportsGameOddsClient (src/server/providers/sportsGameOdds.ts) uses server-side
SPORTSGAMEODDS_API_KEY, the v2 events API, four supported books, alt/opposing odds,
pagination and a monthly object-budget guard. It caps a run at two data requests.
It does not implement the new client's bounded retry/timeout handling.

scripts/import-sportsbook-odds.ts and import-sportsbook-event.ts call
SportsbookIngestionService. It aligns events to the internal NFL schedule, resolves
teams and roster players, normalizes markets, writes mappings/events/markets/prices
and snapshots. It has 24-hour/final-window refresh and started-event locking methods.
No caller of refreshUpcomingEvents or sportsbook cron trigger was found in the
checked-in jobs/workers. workers/content-scheduler is content automation, not odds.
Do not add an extra odds scheduler until the actual deployment schedule is confirmed.

Tables from migrations 035, 038 and 039:
  sportsbook_events: provider + provider_event_id identity, internal UUID, schedule,
    refresh state and locked status.
  provider_team_mappings / provider_player_mappings: provider-scoped identities.
  bet_markets: internal event, player, stat, period, side, threshold, normalized_key,
    raw provider metadata and market-level alternate flag.
  sportsbook_prices: one current price per internal market/book; provider IDs, link.
  sportsbook_price_snapshots: historical prices/availability/links.
Existing uniqueness on (event_id, normalized_key) prevents normalized duplicates.

Repository currently hardcodes SPORTSGAMEODDS for event/mapping writes and player
joins. Line classification reads odd.byBookmaker from legacy JSON, which is not an
Unabated contract. Main/alt is sportsbook-specific and cannot reliably be migrated
using only the shared is_alt_line flag. Current price upserts and snapshots run
per-row; copying this into a board-wide Unabated ingest would multiply DB calls.
Raw legacy JSON can contain the entire odd/bookmaker family repeatedly; new rows
should store only compact identifiers, per-book classification and timestamps.

getLocalEventMarkets serves cached normalized DB rows. Historical-stats services
load existing player logs/context, calculate Lab Score V2 and cache event/mode/model
results. Public Parlay Lab research/event/trending APIs read PostgreSQL; no provider
request should be added to page loads or individual cards. Standard/alt preferences
are shared across web/native, default to -1000, and are already persisted.

My Parlay shares selection identity, odds math, and exact-threshold deduplication in
packages/parlay/slip.ts. Account saves retain snapshots. The existing single-leg
FanDuel adapter validates an exact stored selection URL; there is no verified
multi-leg integration. New Unabated transfers are not registered with either UI.
Save Image, Messages, Share and Save remain unchanged.

Implemented source files
src/server/providers/unabated/client.ts
  Fixed official host; X-Api-Key auth, no redirects, timeout, bounded transient GET
  retries, Retry-After, usage/run ceiling, process-wide five-second odds gate.
  Errors exclude keys, raw upstream response bodies, and returned links.
  Discovery, NFL props odds and standard deep-link methods use documented paths.
src/server/providers/unabated/types.ts
  Runtime schemas from official OpenAPI; reject malformed contract values and
  unsafe integer identifiers; optional data remains optional.
src/server/providers/unabated/coverage.ts
  Shadow-only structured flattening, explicit main vs alternate, availability,
  exact points and independent partner IDs. No parent link/ID reuse for alternates.
src/server/providers/unabated/deeplinks.ts
  Generic Gambly link attribution and conservative Free-tier full-support checker.
  Requires all current exact selections, matching returned IDs and full_support;
  rejects expired/missing freshness, missing IDs, mixed books, same-event legs and
  unsupported links. This is a shadow helper, NOT a DB-backed production service.
src/server/providers/unabated/client.test.ts
  Contract, retries, auth, batching gate, alternate metadata and transfer tests.
src/server/odds/provider-config.ts and sportsbookIngestionService.ts
  ODDS_PROVIDER=unabated blocks accidental paid SportsGameOdds ingestion instead of
  silently falling back. It does not enable unvalidated writes. Current DB reads
  continue serving the stored data. Ingestion/transfer flags are parsed but cannot
  activate incomplete implementations.
scripts/audit-unabated-coverage.ts
  Explicit local-only read-only audit, cross-process PostgreSQL advisory lock,
