Registry and compatibility
BetMGM: internal betmgm, stored BETMGM, SGO betmgm, observed Unabated book BetMGM.
Caesars: internal caesars, stored CAESARS, SGO caesars, observed Unabated book Caesars.
DraftKings: internal draftkings, stored DRAFTKINGS, SGO draftkings, Unabated DraftKings.
FanDuel: internal fanduel, stored FANDUEL, SGO fanduel, Unabated FanDuel.
No numeric provider IDs were invented. Text generation does not consume numeric source IDs.
All use existing passing/rushing/receiving yards and receptions scope, full-game only, one leg
per game. This is application scope, not a guarantee of market coverage at any book.

Existing PostgreSQL resolver is unchanged: same event/player/market/direction/period, actual
available book prices, future unlocked events. It now receives four registered books. No odds
schema migration needed; existing transfer_jobs sportsbook column already stores book identity.
Nearest-line matching retains market-specific maximum distances and favorable-direction tie
breaks. Unknown line classification cannot qualify as a substitute. Original slip is unchanged.
Signed user/book-specific proposals require explicit confirmation for adjustments, then fresh
DB identity/price checks. Preview calls only PostgreSQL, never Unabated.

Shared service and safety
One complete-slip POST for the selected book, bounded polling, no POST retry, short link TTL,
deduplication, authenticated allowlisted local users, same-origin checks, attribution and exact
validation retained. All four books share the existing durable 5/user/day, 50/global/day and
3 concurrent ceilings and one active job per user. The historical actor prefix and job records
remain intact so adding a book cannot reset quotas. Production is blocked independently of flags.
Unexpected player/game/period/market/threshold/book/partial/duplicate results are rejected.
Missing provider direction remains directionVerified:false. Region-specific responses without
reliable region context are rejected; no location selector or default Iowa added.

UI
OPEN IN SPORTSBOOK contains alphabetical full-row controls with book-specific estimated odds
and a small adjustment label when needed. Only complete stored proposals for enabled books are
shown. No matches means the transfer section disappears, leaving existing save/share controls.
Inline preparation/cancellation, explicit adjustment consent, ready state and user-clicked
Continue links retained. Web opens only the validated link on Continue; native uses Linking.
No blank tabs or automatic navigation. Scrollable compact sections preserve room for slip actions.

Provider findings

https://docs.unabated.com/guides/bet-slips

The Free tier lists MGM and Caesars among included providers. Generation/status is included
for Free, but results depend on sportsbook coverage and actual selections. Book inclusion alone
is not proof of a usable complete-slip transfer. Standard deep-link results distinguish full,
partial, event-only and one-bet-only support. Same-game support is Enterprise-specific; our
existing same-game restriction remains. No book-by-book standard/alternate/NFL transfer matrix
or guaranteed state-specific destination is documented. GenerateBetRequest has only type,
generateMobileLinks and content; no state/region parameter. No undocumented region appended.
