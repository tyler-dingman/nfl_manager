FANDUEL TRANSFER UX UPDATE — 2026-10-09

UI AND NAVIGATION
Removed the region dropdown from desktop web, mobile web, and native My Parlay. Eligible selections can start immediately. The button shows Preparing Your FanDuel Slip... and Matching your selections. This usually takes 10–20 seconds.

Generation now stays inline on the existing Parlay Lab screen. No tab or native external link is opened by starting generation or receiving a validated result. The rest of Parlay Lab remains usable. On success, web and native display Your FanDuel Slip Is Ready. and a prominent Continue to FanDuel button. Web uses a user-clicked target=_blank link with noopener/noreferrer; native uses its existing Linking.openURL handler only when Continue is pressed.

Removed the placeholder-tab helper and automatic-navigation callbacks from the shared hook. Loading, cancellation, errors, stale-link cleanup and expiry remain. Existing save/share/export actions remain unchanged. Backend, deduplication, quotas, validation and attribution were not changed for this navigation revision.

REGION FINDING AND BACKEND
Official GenerateBetRequest defines type, generateMobileLinks and content. There is no region/state field or required region query parameter. Our old IA request field and Iowa sentence were application constraints, not documented API requirements.
Sources inspected:
https://docs.unabated.com/guides/bet-slips
https://data.unabated.com/swagger/v1/swagger.json (GenerateBetRequest and generation/status operations)
https://docs.unabated.com/guides/deep-links

The public start request now contains only action and authoritative market UUIDs. Generation text omits the previous Iowa assumption and still includes every DB-resolved player/game/kickoff/market/full-game period/direction/exact threshold. The internal bookkeeping region is UNSPECIFIED (not a sportsbook state or transmitted API parameter); this separates its deduplication key from prior Iowa jobs without changing database tables.

No state is inferred from IP, timezone, or team preference. If returned selection metadata explicitly identifies a region, the region-neutral validation path refuses the URL with a clear region-specific-selection error rather than guessing. The older internal IA validation remains for already-created IA jobs. Exact-selection checks and strict independent-offer validation remain intact. Missing direction and region metadata are not claimed as independently verified.
