Unabated NFL Props diagnostic report
Run: 2026-10-10 UTC / 2026-10-09 America/Chicago

Conclusion
NFL straight odds and the independent deep-link/bet-generation workflows work for
this Free content-partner account. NFL AND MLB props boards fail, and both tested
sources endpoints fail. The most likely explanation is a provider-side problem in
these scoped market routes or the account's configuration for those routes. It is
not an entire-API outage, a missing API key, or simply absent NFL prop inventory:
the independent generator found a Bears FanDuel player prop.
An account-specific scope/configuration problem cannot be excluded with one key.

Implementation verification
Base: https://data.unabated.com. Header: X-Api-Key. Method: GET for odds/discovery.
Both NFL odds paths were called without query parameters. Existing client uses the
same documented host/header/paths and no filters on props. No undocumented event,
book, period or league query filters are present. The only implemented optional
odds filter in the diagnostic script is documented betTypeId, conditionally skipped.
No installed odds scheduler was found in source; Cloudflare worker is content-only.
Local process checks showed zero other named ingestion/audit processes. External
hosts cannot be ruled out from a local process check. No 429 or Retry-After appeared.
Diagnostic odds calls waited 5.5 seconds after the preceding odds response completed;
no failing endpoint was retried. A five-second startup delay followed the UI test.
The shared client was also tightened to wait five seconds after a run completes,
rather than only spacing request start times. This did not explain these failures:
they persisted in independently spaced raw requests and contained no rate-limit signal.

Cause assessment
1. Incorrect request implementation: unlikely; raw requests match the official
   examples, bypass app schemas, and straight odds plus links work.
2. Unsupported query parameters: ruled out for these failures; none were supplied.
3. Account permissions: key and some Free scope work; route-specific account
   configuration remains possible. No 401 or 403 was observed.
4. Rate limiting: no evidence; spacing enforced, no 429, no Retry-After.
5. Provider failure: leading explanation for repeated application errors spanning
   multiple prop leagues and both source-discovery routes.
6. Missing market coverage: insufficient explanation for these explicit errors;
   generator returned a real NFL player-prop candidate. Actual full coverage is
   still unknown and cannot be inferred from one candidate.

Development continued without production changes
- scripts/diagnose-unabated.ts records the matrix, sanitized raw errors, timings and
  counts. It never retries an identical application-level error.
- scripts/diagnose-unabated-links.ts runs independent real-ID/text-only link tests;
  it reads only local DB data and keeps transfer settings unchanged.
- normalize.ts now produces compact DB-ready rows against injected, reviewed
  canonical mappings. It preserves exact lines, side, internal event/player IDs,
  book-specific main/alternate status, provider and sportsbook IDs separately,
  original provider deep link and freshness. Unknowns and conflicting duplicates
  are quarantined. No guessed numeric market map is shipped.
- generated-slip.ts rejects missing independent identity/direction resolution,
  wrong thresholds, wrong regions, unavailable/expired offers, duplicates, partial
  slips and invalid generated URLs. This is not registered with the My Parlay UI.
- Fixture tests cover canonical mapping, -1000 alternate odds, Over/Under, duplicate
  prevention, unknown mappings and unsafe generated-slip matches. Production data,
  legacy integration, existing UI and ENABLE_FANDUEL_BETSLIP were not changed.
No database migration or writer was applied in this diagnostic step.
