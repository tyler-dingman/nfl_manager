## PostgreSQL dependency and polling findings

The machine-readable table list retains names and declaring paths. Runtime odds schemas add tables beyond numbered migrations. Dependency matches include JSONB in 56 files, transactions in 34, arrays in 20, row locking in 13, advisory locking in five and vector-related SQL in six. Counts are static indicators, not executed-query totals.

`three-and-out-daily.yml` calls delivery every five minutes. Delivery reads preference/snapshot candidates and claims delivery rows. This can prevent Neon's five-minute idle suspension; removing this one cron would still not prove scale-to-zero under geographically distributed user traffic. Nightly search, content scheduling and data imports also wake PostgreSQL. Existing account/session requests, user content, reward accounting, Front Office, Parlay, search and commerce still use it.

D1 metadata migration candidates: preferences, session/credential metadata, saved IDs, source checkpoints and bounded odds directories. Port transactions deliberately, colocating an owner's state and command receipts. Put immutable game references and large odds/raw/editorial payloads in private R2. Preserve ownership/version CAS and read-back checks. PostgreSQL `FOR UPDATE`, advisory locks, JSONB operators, array queries and vector ranking are not direct SQLite substitutions. Front Office permits replay responses up to 64MiB before compression; D1's 2MB row ceiling prevents a blind move. Sharding does not solve account-wide writes or cross-database atomicity.

## AI budget sensitivity

ASSUMED, not measured token counts: two searches/DAU/day, 25% answer-cache hits, 2,000 input and 256 output tokens per miss; 83 generated stories/day at 3,000 input and 600 output tokens. Candidate `@cf/qwen/qwen3-30b-a3b-fp8` is priced at 4,625 neurons/million input and 30,475/million output tokens; BGE-small at 1,841/million input. These model substitutions have not been quality-approved.

At 1k DAU, search alone is ~25,577 neurons/day. Editorial generation adds ~2,669 and an example embedding workload adds ~365, totaling ~28,612 before audio/retries, above the 10k allowance and 7k headroom target. At 1.5k/2k DAU the same assumptions are approximately 41.5k/54.4k neurons/day. Precomputation and source-version-aware cache reuse may help, but no cache hit rate or equivalent answer quality was established for this replacement. The current BGE embedding width matches [Cloudflare BGE-small](https://developers.cloudflare.com/workers-ai/models/bge-small-en-v1.5/); compatibility of vectors still needs retrieval evaluation and complete reindexing if normalization differs.

## Source and odds admission

The merged source audit has 332 unique URL-backed identities, 164 technically verified feeds, and zero new rights-approved automated sources. The 46 new registrations stay disabled; no added live cost is authorized. Existing registry aliases/publisher relationships and attribution remain intact. Nominal feed cadence is not actual scheduled throughput: existing global runs and batch caps constrain ingestion. Prior modeled 1,040 daily source checks and 200 candidates/day are planning inputs, not current provider usage. The enabled 400-candidate scenario in the source audit already exceeds the D1 target (~529MB/year, ~88.8k writes/day); source expansion is not absorbed into the lean baseline automatically.

The new isolated schedule primitive has Monday/Wednesday/Saturday 15:00 UTC slots, no automatic ambiguous retry, and durable duplicate protection. It is not connected to production cron/provider ingestion. Existing prices, alternate lines through -1000, book flags, transfer selections, and history remain intact. Production integration still needs a reviewed provider dispatcher, account-wide durable request/object budgets, precomputed board summaries and actual stored snapshot timestamps in web/native freshness UI. No new claim that a three-times-weekly snapshot is live was added.
