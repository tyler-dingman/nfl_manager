# Local Node staging prototype

This opt-in path retains the existing application and route discovery. Existing Cloudflare deployment configurations do not reference it. No deploy, service-creation, migration, billing or provider-activation command is included.

## Reproduce locally

Use the existing installed Node 22 dependencies. Run from the repository root:

```sh
node scripts/render-staging/build.mjs
TSX_TSCONFIG_PATH=tsconfig.test.json NODE_OPTIONS='--require ./scripts/phase-two-network-guard.cjs' node --import tsx --test tests/render-staging/adapter-security.test.ts tests/render-staging/domain.test.ts
TSX_TSCONFIG_PATH=tsconfig.test.json NODE_OPTIONS='--require ./scripts/phase-two-network-guard.cjs' node --import tsx tests/render-staging/integration.ts
TSX_TSCONFIG_PATH=tsconfig.test.json NODE_OPTIONS='--require ./scripts/phase-two-network-guard.cjs' node --import tsx --test src/server/auth/*.test.ts src/lib/application-session.test.ts packages/parlay/*.test.ts
```

The isolated build allows only its existing Google Fonts download. Tests require permission to bind loopback sockets; the network guard blocks outbound application sockets. Browser tests require installed Google Chrome (`channel: chrome`). All browser traffic is intercepted; unrecognized requests are blocked. Test Firebase SDK traffic uses a supported loopback emulator transport with synthetic, genuinely RSA-signed tokens verified by the unchanged application verifier. No live Firebase project is contacted.

Output: `.staging/render-node/api.mjs`, `start.mjs`, `app/` (standard production Next API/SSR build), and `assets/` (the same build's public files and `_next/static`). Pair these assets with this Node build, never with an older OpenNext build. Build outputs are ignored. Evidence goes under `reports/render-free-prototype/`.

## Security and recovery boundaries

The HMAC assertion binds method, canonical public origin, path/query, filtered headers, body hash, audience, issuance, expiry and random nonce. It lasts20seconds; raw public origin headers cannot establish user identity. A durable unique nonce claim in the existing D1_USERS assertion table rejects replays across replicas/restarts before dispatch. Node SSR's session lookup signs a separate request to loopback; application user/session/revocation checks remain unchanged. Raw forwarded/client-IP headers are discarded; Node rate limiting conservatively shares the unknown-client bucket, a usability limitation requiring review before hosted use.

All statements remain owner-fixed and parameter bound. One adapter batch is exactly one REST POST; it is never decomposed into sequential calls. Remote atomicity is unverified, so required user/session/fence/idempotency and nonce transactions fail closed. Only a loopback fixture can opt in to native D1 batch semantics. Those local tests cannot certify Cloudflare REST transactions.

Retain the independent erasure ledger and coordinated ten-database snapshot/recovery checks. Restore only into empty isolated targets. Keep traffic stopped during recovery, then wait at least30seconds after restore (and keep clocks synchronized) before reopening so restored/rolled-back nonce history cannot enable replay of a still-valid assertion. Do not restore occupied staging resources to make space. No automatic retries occur for ambiguous REST mutation outcomes or origin timeouts; use the existing command idempotency checks only after a newly authenticated request.

Render cold starts can exceed the15second proxy timeout and20second assertion lifetime. The request must fail closed; no automatic retry extends an assertion. Free eligibility, isolated service memory, billed CPU, actual quotas, REST atomicity, provider compatibility and cold-start UX remain hosted blockers. See the root report before considering a separately authorized hosted experiment.
