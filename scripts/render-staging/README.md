## Future wiring for review only

Reuse the existing Web Worker and private API Worker; do not create a Worker or database. Web uses `workers/staging/render-origin.ts`, matching `ASSETS` with `run_worker_first=true`, existing staging gate settings, native `D1_USERS`, and existing private `API_SERVICE`. API uses `workers/staging/transaction-api.ts` and the same ten existing D1 bindings. Keep its workers_dev, previews and routes disabled. The other three staging Workers remain private and unchanged; no password Worker or background trigger is invoked.

Normal assets/API/SSR requests first pass the existing staging access gate. Dynamic requests then reach the authenticated Render origin. The reserved `/__staging/transaction` path instead requires a separate server-only transaction capability before dispatch; a browser gate cookie is insufficient. Web verifies the assertion and atomically claims its nonce in native D1 before calling the private API service. API rechecks the assertion, validates fixed logical owners and bound statements, and executes a batch in exactly one native `db.batch()` call. The two invocations retain separate query budgets: Web replay claim 4 statements; API transaction at most 50 statements. No batch is split or retried.

Render keeps existing API/SSR computation and Firebase verification; all database execution is inside Cloudflare. This is the smallest adaptation of the existing prototype, rather than moving 201handlers back into a heavy Worker. It is not the public D1 REST API. The gateway is a privileged server capability, not an end-user SQL feature: application routes never forward client SQL, database IDs, owners or capability headers. SQL and parameters are generated by the existing server repositories. Authentication/ownership checks remain in the application. Possession of the private transaction secret grants server-level data access and must be treated accordingly.

## Failure, recovery and limits

Assertions bind audience, method, public URL/path/query, headers and body digest; they expire after 20 seconds and require a durable single-use claim. Origin assertions and transaction assertions use distinct secrets/audiences. Raw forwarded/user headers cannot grant trust. TLS, manual redirects, bounded payload/results, timeouts, sanitized errors and no automatic retries preserve ambiguous-outcome safety. Database BLOB parameters use bounded base64 to retain chunk batch sizes without JSON number-array expansion. Do not split an atomic operation to fit a transport limit.

Maintenance locks stop runtime gateway traffic, including reads. Schema/restore/admin SQL is deliberately outside this application gateway. The existing owner-only native recovery tools remain the supported path: stop writers, coordinate all ten databases, retain the current independent erasure ledger, restore only into empty isolated targets, verify references/integrity, and unlock only after completion. Wait at least 30 seconds after restoring nonce history before reopening traffic. No migration or recovery against occupied hosted databases is authorized here.

The protocol tests prove rollback and concurrent CAS on the actual native binding, not public REST atomicity. They do not establish hosted CPU or Render memory fit. Hosted validation must measure both Web/API Worker CPU, D1 rows (including roughly3 nonce-ledger writes per gateway request plus expiry cleanup), Worker request amplification, origin service memory/concurrency and cold starts. A Render cold start can exceed the 15 second proxy timeout/20 second assertion; fail closed and require a fresh request. No paid workaround or automatic mutation replay is enabled. Raw client IP headers remain discarded, so Node uses a conservative shared unknown-client rate bucket.

## Portable hosted packaging and observation

Render uses Node 22, `npm ci --include=dev && npm --prefix workers/content-engine ci --include=dev && node scripts/render-staging/build.mjs`, then `node .staging/render-node/start.mjs`. Temporary builds use the OS temporary directory and portable copy-on-write copying, excluding environment files and credential directories. Auto-deploy stays off.

Origin responses enforce private/no-store cache headers even when Next supplies public static cache headers. Operator-only `GET /__staging/runtime-observation` requires a fresh signed assertion with audience `dd-render-staging-runtime-observer`; the normal edge audience is rejected. It exposes numeric process memory, cumulative process CPU and uptime only. CPU deltas include concurrent process activity and are not Cloudflare billed CPU. Cloudflare live-tail CPU must be captured separately for both gateway hops. No authorization decisions are cached.
