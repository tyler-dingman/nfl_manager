# Phase 4 recovery scale rehearsal

**MEASURED synthetic local workerd, not production RPO/RTO.** 3,000 users, 3,000 saved bets, 101 game owners, 401 versions, credentials/preferences/sessions, synthetic editorial/odds bodies, a high-entropy 2.1 MB game document, 74 logical tables, 15,535 rows and 1,603 R2 objects. User IDs, saved IDs, row hashes, object hashes and foreign keys survive exact restore.

Full backup: 16.13 s. Interrupted restore resumed to READY: 21.28 s for the resumed call, not total interrupted+resumed wall time. Repeated idempotent restore: 10.90 s. Identical checkpoint: 18.95 s, same ID, zero additional directory/body writes. These values include local I/O and verification, not production CPU.

Injected partial body-backup failure publishes no completed checkpoint; retry succeeds. Interrupted restore keeps target unserved; repeat resumes via chunk receipts. Exact final table and object verification and FK checks gate READY. Existing corruption, missing-object and wrong-key tests remain. JSON-tree edges are verified before checkpoint publication, not merely top-level pointers. Raw physical compressed bodies are copied and logical identities validated. Original uncompressed and encrypted Phase 3 checkpoints remain readable.

R2 operation totals across failure, successful checkpoint, duplicate checkpoint, interruption, resumed and repeated restore: `{"source": {"reads": 12087, "writes": 0, "lists": 10, "bytesWritten": 0}, "backup": {"reads": 12846, "writes": 1603, "lists": 0, "bytesWritten": 1478224}, "target": {"reads": 9663, "writes": 1603, "lists": 0, "bytesWritten": 1478224}, "directoryPhysicalBytes": 523133, "directoryWrites": 27}`. These are cumulative totals, **not per-backup billing**. D1 logical fixture storage 6,021,120 bytes; page/index/column attribution is retained in JSON. D1 seed metrics are not presented as recovery-operation counts. Cumulative backup D1 operations: `{"d1Calls": 15, "statements": 375, "rowsRead": 80550, "rowsWritten": 0}`. Cumulative restore D1 operations: `{"d1Calls": 1352, "statements": 17103, "rowsRead": 77089, "rowsWritten": 46365}`. They include failure/repeat calls rather than representing one clean invocation. Row counts and bounded 40-row restore batches are verified.

Limits retained: explicitly stopped writers, new unserved schema-matched target, 64 MB in-memory table ceiling, 900 KB row chunks, bounded object sizes and local tooling outside one production request. This is materially larger than Phase 3's 132-row rehearsal but is not an annual whole-product population. Streaming/online export, production-scale peak load, off-account encryption/key recovery, automated cutover gates and reference-safe retention remain blockers. No active backup pruning discards required rollback history.
